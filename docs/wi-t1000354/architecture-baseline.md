# 架构基线：生气脸界面（WorkItem: wi-t1000354）

## 1. 需求基线引用

本设计基于已批准的需求基线 `docs/wi-t1000354/requirements.md`（sha256: c4366d376df8f5e69a64f8087cd201b94e9a1326ec156e02e6b2f62e0286f1f7）。产品语义（表情元素构成与「生气」可辨识性）以该基线为准，本设计不扩展、不重裁。

## 2. 路线结论

应用类型为 `simple-frontend`（compact 路线）：页面为纯静态浏览器图形展示，无登录、无数据存取、无后台任务、无外部服务集成、无共享数据。设计不引入任何服务端组件。

## 3. 页面与交互范围

- 单一页面，打开即完整渲染生气表情图形：圆形脸部、左右两条向眉心方向下压的皱眉、眉毛下方左右各一只清晰可见的眼睛、两端向下弯曲的下撇愤怒嘴型。
- 无交互、无动画：需求将动画与交互效果保留为未规定事项，本设计不引入。
- 页面自包含，不加载外部资源（无外链 CSS、JS、图片或字体），保证离线直接打开即可完整呈现。

## 4. 技术承载方式

- 交付物为单文件静态 HTML 页面，表情图形以内嵌 SVG 描述。
- 选型理由：SVG 由浏览器原生渲染，无需构建工具与运行时依赖；矢量图元可精确控制脸部圆形、眉毛、眼睛、嘴型的形状、位置与颜色，直接满足「浏览器打开即可查看」的验收方式，且在无 JavaScript 环境下仍可完整呈现。
- 不采用的备选：CSS 纯图形对曲线嘴型控制繁琐；Canvas 需要脚本绘制，无脚本时无任何降级呈现；React/Vite SPA 面向带数据读写的单用户 CRUD 场景，本任务无任何数据记录需求，引入构建链与「本地直接打开页面文件」的基线相悖。
- 图形具体参数（尺寸、坐标、配色）属需求未规定范围，由实现阶段自行确定，不构成验收约束。

## 5. 浏览器状态与数据归属

- 页面无状态：不读写 localStorage、sessionStorage、Cookie 或 IndexedDB；页面内容静态，重复打开呈现一致，无需要保留的业务数据。
- 无服务端权威数据、无认证/权限、无后台任务、无外部服务集成、无跨设备/跨用户同步层。

## 6. 实现入口与运行方式

- 实现入口：一个自包含的 HTML 文件，由实现阶段在工作区源码写范围内确定文件名（建议 `index.html` 置于工作区根目录）。
- 运行方式：浏览器直接打开该 HTML 文件（本地文件协议）即可查看，无需安装依赖、无需构建、无需启动开发服务器。
- 如需通过 HTTP 预览，可由任意静态文件服务器承载同一文件，但这不是验收必需条件。

## 7. 设计边界

- 本路线不生成技术契约、工作区初始化、ADR 或实现计划。
- 本设计冻结的架构结论：单文件静态 HTML + 内嵌 SVG、无状态、无外部依赖、本地直接打开。后续实现与验证阶段复用该结论。
